# Task02 Егор Макаренко

1) Из двух сигналов

   ```text
   y1[n] = x[n - 1] + x[n] + x[n + 1]
   y2[n] = y2[n - 2] + y2[n - 1] + x[n]
   ```

   на GPU **проще реализовать первый** (y1), так как результат операции, выполняемой каждым отдельным потоком, зависит только от входных данных в x, которые изначально известны и доступны всем потокам, и не зависит от работы соседних потоков. y2 реализовать сложнее из-за рекурсивной зависимости, где каждый поток должен дождаться результата от двух предыдущих, что не позволяет производить вычисления параллельно.

   Ответ: y1.

2) При размере рабочей группы (32, 32, 1) с размером warp/wavefront в 32 work item'а каждый warp/wavefront будет обрабатывать подзадачу размера (32, 1, 1), где get_local_id(0) изменяется от 0 до 31, get_local_size(1) равно 32, а get_local_id(1) принимает одно и то же значение в диапазоне [0, 32) для всего warp'а. Следовательно, в коде

   ```c
   int idx = get_local_id(1) + get_local_size(1) * get_local_id(0);
   if (idx % 32 < 16)
       foo();
   else
       bar();
   ```

   остаток idx % 32 будет равен get_local_id(1), и **code divergence не произойдёт**, так как все work item'ы в рамках одного warp'а получат одинаковый результат в условии - true для warp'ов 0-15 и false для warp'ов 16-31.

   Ответ: code divergence не произойдёт.

3) При размере рабочей группы (32, 32, 1) с размером warp/wavefront в 32 work item'а и выровненном по размеру кэш линии в 128 байт указателе data:

   a) `data[get_local_id(0) + get_local_size(0) * get_local_id(1)] = 1.0f;`
      Данное обращение к памяти **будет coalesced**, так как внутри каждого warp'а `get_local_size(0) * get_local_id(1)` принимает одинаковое значение (32 * номер warp'а в workgroup), и обращение происходит к последовательно лежащим элементам в памяти для get_local_id(0) в диапазоне [0, 32). При этом произойдёт **32 записи кэш линий** - по одной в каждом warp'е.

      Ответ: coalesced, 32 записи.

   b) `data[get_local_id(1) + get_local_size(1) * get_local_id(0)] = 1.0f;`
      Данное обращение к памяти **не будет coalesced**, так как внутри каждого warp'а `get_local_id(1)` принимает одинаковое значение (номер warp'а в workgroup), и последовательно расположенные work item'ы в warp'е обращаются к памяти с шагом в 32 * sizeof(float) = 128 байт. Таким образом, каждый warp запишет по одному элементу в 32 кэш-линии, общее число записей workgroup - **1024 кэш-линии**.

      Ответ: не coalesced, 1024 записи.

   c) `data[1 + get_local_id(0) + get_local_size(0) * get_local_id(1)] = 1.0f;`
      Данное обращение к памяти отличается от пункта a) смещением на 1, а значит, последний элемент каждого warp'а будет записан в отдельную кэш линию. Такое обращение **не будет coalesced**, так как потребуются две транзакции в память в каждом warp'е, при этом будет записано **64 кэш линии**.

      Ответ: не coalesced, 64 записи.
